* Guia de Referência Moderno: Git & GitHub - Prof. Bueno
* Configuração Inicial & Autenticação
Antes de começar, garanta que sua identidade e métodos de acesso ao github estão configurados.

** Baixar o git
- Linux (Debian/Ubuntu): =sudo apt install git=
- Fedora: =sudo dnf install git=
- Windows/Mac: http://git-scm.com

** Identidade Básica
Configura seu nome nas "etiquetas" dos commits.
#+begin_src sh
  git config --global user.name "Seu Nome"
  git config --global user.email "seu_email@exemplo.com"
  git config --global core.editor "emacs"  # ou code, vim, nano
  git config --global init.defaultBranch main  # Padroniza 'main'
  git config --global pull.rebase true         # Evita merges desnecessários ao baixar
  git config --global color.ui auto
#+end_src

** Autenticação Moderna (SSH)
O GitHub não aceita mais senha de usuário no terminal. Use Chaves SSH.
1. *Gerar Chave:*
   #+begin_src sh
     ssh-keygen -t ed25519 -C "seu_email@exemplo.com"
     # Dê Enter em tudo (sem passphrase para agilidade)
   #+end_src
2. *Ativar Agente:*
   #+begin_src sh
     eval "$(ssh-agent -s)"
     ssh-add ~/.ssh/id_ed25519
   #+end_src
3. *Copiar e Colar no GitHub:*
   Exiba a chave com =cat ~/.ssh/id_ed25519.pub= e cole em *Settings -> SSH keys*.

* GitHub: Primeiros Passos

** Criar Repositório (Do Zero)
1. No site, clique em *New repository*.
2. *Dica:* Se for subir um código que já existe no seu PC, crie o repo *VAZIO* (sem README/gitignore).

** Clonar Repositório Existente
#+begin_src sh
  # Use SEMPRE a opção SSH (git@github...)
  git clone git@github.com:usuario/nome-do-projeto.git
  ex:
  $ Ajuda
  git clone https://github.com/ldsc/LDSC-Ajuda-DocumentosAuxiliares
  # Modelo de projeto completo
  git clone https://github.com/ldsc/LDSC-ProjetoEngenharia-2-Software-TituloProjeto-ModeloCompleto
#+end_src

** Adicionar Colaboradores
Settings -> Collaborators -> Add people (insira o email do aluno/colega).

* Fluxo de Trabalho Diário
A rotina sagrada do desenvolvedor.

** Verificar Estado (O comando mais importante)
#+begin_src sh
  git status  # Mostra o que mudou e onde você está
#+end_src

** Preparar (Staging)
#+begin_src sh
  git add .              # Adiciona TUDO (novos, modificados, deletados)
  git add -u             # Adiciona apenas modificados (ignora arquivos novos)
#+end_src

** Salvar (Commit)
#+begin_src sh
  git commit -m "verbo/ação: o que foi feito"
#+end_src

** Sincronizar (Sync)
#+begin_src sh
  git pull origin main    # Baixa atualizações
  git push origin main    # Envia seus commits
#+end_src



* Padrões de Nomes (Branches e Tags)
Evite dores de cabeça seguindo convenções universais.

** Prefixos Recomendados
Para criar branches organizadas (=git switch -c nome=):
| Prefixo     | Uso                                   | Exemplo                          |
| :---        | :---                                  | :---                             |
| =feat/=     | Nova funcionalidade                   | =feat/nova-interface-grafica=    |
| =fix/=      | Correção de erro (bug)                | =fix/correcao-calculo-imc=       |
| =docs/=     | Apenas documentação                   | =docs/atualiza-readme=           |
| =refactor/= | Melhoria de código (sem mudar função) | =refactor/limpeza-classe-pessoa= |

** O que NÃO fazer (Proibido)
1. *Espaços:* Jamais use espaços. Use hifens (=minha-branch=) ou underscores.
   - ❌ =corrigir erro= | ✅ =fix/corrigir-erro=
2. *Acentos e Cedilha:* Evite caracteres latinos, pois terminais Windows/Linux podem divergir na codificação.
   - ❌ =correção-do-cabeçalho= | ✅ =fix/correcao-cabecalho=
3. *Nomes Vagos:*
   - ❌ =teste=, =temp=, =ajuste=, =seuNome=

** Tags de Versão (Semantic Versioning)
Use o padrão =vX.Y.Z=.
- =v1.0.0= (Major): Mudança que quebra compatibilidade.
- =v1.1.0= (Minor): Nova funcionalidade (compatível).
- =v1.1.1= (Patch): Correção de bug simples.

* Manipulação de Branches (Modernizado)

| Ação             | Comando Moderno           | Comando Antigo (Legacy)     |
| :---             | :---                      | :---                        |
| *Criar e Mudar*  | =git switch -c feat/nome= | =git checkout -b feat/nome= |
| *Mudar de Ramo*  | =git switch feat/nome=    | =git checkout feat/nome=    |
| *Voltar p/ Main* | =git switch main=         | =git checkout master=       |
| *Deletar Ramo*   | =git branch -d feat/nome= | =git branch -d feat/nome=   |


* Correções, Ajustes e "Salva-Vidas"

** Desfazer alterações locais (Antes do Commit)
#+begin_src sh
  git restore arquivo.txt       # Descarta mudanças no arquivo
  git restore .                 # PERIGO: Descarta TUDO não salvo
#+end_src

** "Guardar para depois" (Stash)
Útil para interrupções rápidas (ex: corrigir bug urgente na main).
#+begin_src sh
  git stash                   # Guarda trabalho incompleto
  git switch main             # Muda de branch
  # ...corrige bug...
  git switch feat/minha-branch
  git stash pop               # Recupera o trabalho
#+end_src

** O Botão de Pânico (Reset)
#+begin_src sh
  # Destrói commits locais e deixa igual ao último ponto salvo
  git reset --hard HEAD
#+end_src

* Ferramentas e Interfaces Gráficas
Nem tudo precisa ser feito no terminal.

** Clientes Git (GUIs)
Facilitam a visualização do histórico e resolução de conflitos.

1. *GitKraken:* (Linux/Win/Mac)
   - Visualmente o mais bonito e poderoso. Gratuito para repos públicos.
   - Site: https://www.gitkraken.com

2. *Gitg:* (Linux - GNOME)
   - Simples e leve, ótimo para ver o histórico.
   - Instalação: =sudo apt install gitg= ou =sudo dnf install gitg=

3. *Git Cola:* (Linux - FOSS)
   - Interface rápida e funcional.
   - Instalação: =sudo apt install git-cola=

** Plugins para Editores (Essenciais)

*** Para Alunos (VS Code)
- *GitLens:*
  - O padrão de mercado. Mostra quem editou cada linha (Blame) direto no código e histórico visual.
- *Git Graph:*
  - Cria o desenho da árvore de commits dentro do VS Code.

*** Para o Professor (Emacs)
- *Magit:* É indiscutivelmente a melhor interface de Git já criada para qualquer editor.
  - Permite fazer stage de pedaços de código (hunks), rebase interativo e commit com poucos atalhos.
  - Instalação: via MELPA (=M-x package-install RET magit=).

* Receitas Práticas (Exemplos)

** 1. Commit com Data Passada
#+begin_src sh
  git add .
  git commit -m "Implementação do módulo X" --date="2026-01-20 14:00:00"
#+end_src

** 2. Criar Tags de Versão (Releases)
#+begin_src sh
  git tag -a v0.2.4 -m "Versão com correção do bug de login"
  git push origin v0.2.4
#+end_src

** 3. Corrigir mensagem do último commit
#+begin_src sh
  git commit --amend -m "Nova mensagem correta"
  # CUIDADO: Não faça isso se já deu push!
#+end_src

** 4. Sincronizar um Fork (Upstream)
Atualizar seu projeto com o original do professor.
#+begin_src sh
  git remote add upstream https://github.com/professor/projeto.git
  git fetch upstream
  git switch main
  git merge upstream/main
  git push origin main
#+end_src
